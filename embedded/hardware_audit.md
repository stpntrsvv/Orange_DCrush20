# Первый аудит подключённого контроллера

Дата: 2026-09-25. Выполнялось только определение интерфейса; flash не стирался и
не программировался.

- USB-устройство: `STM32 STLink`, VID:PID `0483:3752`.
- Серийный номер: `0668FF545771485067173011`.
- Версия отладчика: `STLINK V2J43M28`, API v2.
- Напряжение цели: около `3,26 В`.
- Виртуальный COM-порт: `/dev/cu.usbmodem1102`.
- macOS сообщает `busy 0`; COM-порт локальным процессом не удерживается.

Точная плата: WeAct Studio STM32H7R3Zx CoreBoard V1.0, MCU
`STM32H7R3Z8J6`. По официальной схеме разъём P5 идёт сверху вниз:

1. `VDD33`;
2. `SWDIO` / `PA13`;
3. `SWCLK` / `PA14`;
4. `GND`.

`NRST` на P5 не выведен. Аппаратный connect-under-reset без отдельного
провода к `NRST` невозможен; кнопку Reset можно удерживать вручную.

Первичная ошибка `stm32h7x.cpu0 examination failed` не означала
неисправность SWD. Типовой OpenOCD 0.12.0 `target/stm32h7x.cfg` ищет
Cortex-M на Access Port 0, а STM32H7R3 предоставляет ядро через Access Port 1.
Это согласуется с `access_port_id=1` в официальном примере WeAct.

Прямой опрос AP1 успешен:

- SWD DPIDR: `0x6ba02477`;
- ядро: Cortex-M7 r1p2, 8 breakpoints, 4 watchpoints;
- CPUID по адресу `0xE000ED00`: `0x411FC272`;
- после halt: `PC=0x900006A8`, `MSP=0x200005D0`.

`PC` подтверждает исполнение заводского приложения из внешней XSPI flash,
отображённой с `0x90000000`. Плата, ST-LINK и четыре линии P5 исправны.
Ни flash, ни option bytes во время аудита не изменялись.

## Первый Rust `no_std` запуск

RAM-only образ успешно исполнен 2026-09-25. Код и стек были в верхних 7 КБ
AXI SRAM, результат — в DTCM. OpenOCD проверил все 568 загруженных байтов
до пуска. Получены маркеры `ORNG`/`DONE`, 826 тактов DWT и точное
совпадение `f32`-результата с host-тестом (`0x417BF243`). После Reset
заводской код снова исполнялся из `0x90000000`. Flash не изменялась.
