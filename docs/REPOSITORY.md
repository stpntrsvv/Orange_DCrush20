# Структура и воспроизведение

Подготовлено 2026-10-06. Проект — исследовательская модель и RAM-стенды,
а не готовый образ непрерывного гитарного устройства.

## Зачем сохранены эти пути

`firmware/` содержит Cargo workspace; `simulation/` — модели и действующие
команды, `simulation/experiments/` — неизменные результаты по опытам.
Их перенос изменил бы Python-импорты, генераторы, fixture-пути Rust и
манифесты снимков. Вместо этого одноразовые переписывающие скрипты вынесены
в `simulation/history_tools/`, а прежние планы и передачи — в `docs/history/`.
Принятые архивы и источники опытов сохранены в исходных каталогах.

`csrc/` документирует допустимую границу CMSIS-DSP; собственных C-драйверов
там нет. `tests/` — описание проверок; реальные Rust-тесты встроены в
`firmware/orange-dsp`, Python-проверки находятся в `simulation/`.
`tmp/`, `.venv/`, `.vscode/` и любые `target/` локальные и не входят в Git.

В репозитории много прежних вариантов: их наличие не делает их рабочей базой.
Текущий путь обозначен в [STATUS](STATUS.md) и [firmware](../firmware/README.md).

## Инструменты

Проверенная локальная среда: macOS Apple Silicon, Python 3.14.6,
NumPy 2.5.3, Rust 1.98.1, ngspice 47. Это запись проверенного окружения,
не утверждение об исключительной совместимости с этими версиями.
Для схемных проверок нужен ngspice; для RAM-стендов — OpenOCD/ST-Link и плата.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
python3 tools/check_repository.py
```

Rust/Cargo должны быть в `PATH`. Настройки `firmware/.cargo/config.toml`
по умолчанию выбирают `thumbv7em-none-eabihf` и linker script контроллера.
Для выполнения на компьютере **явно** указать host target:

```sh
cd firmware
cargo test -p orange-dsp --lib --release --target aarch64-apple-darwin --features noise48-candidate
```

Команда проверена на Apple Silicon. Для другой платформы сначала проверить
низкоуровневую арифметику: `sqrt64` нынешнего ядра реализован для ARM/AArch64;
вне этих архитектур он пока не вычисляет корень. Простая замена имени target
на x86 не подтверждает численную корректность. Инструменты аппаратного анализа
также содержат прежние пути Homebrew и host-target Apple Silicon.

Два Rust-теста помечены `ignored` и требуют сохранённых текстовых эталонов
`absolute_ports/reference_*.txt`; они включены в Git. Запуск вместе с ними:

```sh
cargo test -p orange-dsp --lib --release --target aarch64-apple-darwin --features noise48-candidate -- --include-ignored
```

Для сборки текущей парной аппаратной пробы:

```sh
rustup target add thumbv7em-none-eabihf
cargo build -p h7r3-runtime --bin tda48-probe --release --features fpu-roots,orange-dsp/tda48-baseline
```

Это **сборка**, не пуск платы. RAM-серии готовит `run_tda48_hardware.py`,
анализирует `analyze_tda48_hardware.py`; перед пуском проверить подключение,
свежий ELF, вход и контрольные точки. После RAM-пробы — `reset run` и проверка
штатного приложения/fault-регистров. Flash не писать.

## Данные и безопасное воспроизведение

Исходники, схемы, отчёты, JSON-метрики, текстовые эталоны и журналы в Git.
Аудио, бинарные траектории, NPZ, PCM и точные ELF — в Releases:
[восстановление](../artifacts/README.md). Без архива исходники можно читать,
собирать и выполнять проверки по включённым fixture; воспроизведение длинной
гитары и аппаратных серий потребует архивных входов.

Для новой генерации только коэффициентов, из корня:

```sh
.venv/bin/python simulation/generate_rate48_coefficients.py --out /tmp/orange-coefficients-new
```

Выходной каталог должен быть новым. Алгоритм и принятые исходники не перезаписываются.
Генератор проверяет совпадение с живыми коэффициентами через `manifest.json`.
Для нового парного host-контроля пример `tda48_compare` принимает новый
выходной каталог и PCM16-вход; команды и формат — `firmware/README.md`.

Исторические примеры `rate48_di`, `rate48_sine` и многие `run_*.py`
пишут в фиксированные каталоги опытов. Их нельзя запускать пачкой «для проверки
всего» поверх сохранённых результатов. Скрипты `implement_*` — история
создания старых вариантов, не средство обновить принятый DSP.

## Происхождение и права

Это сторонняя схема и параметрическая модель, не официальный продукт Orange
и не подтверждённая копия конкретного серийного аппарата. Происхождение PDF
и контрольные суммы записаны в `reference/`. Сторонние схемы и даташиты
сохраняют права их авторов. Лицензия для собственного кода пользователем
ещё не выбрана; публикация не добавляет выдуманную лицензию.
