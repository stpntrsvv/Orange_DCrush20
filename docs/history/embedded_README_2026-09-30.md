# Embedded

Синий светодиод заводского `01-Blink` подключён к PB2. Для временного
погашения без записи flash, после пуска заводского приложения:

```sh
openocd -f embedded/openocd/weact_stm32h7r3.cfg -f embedded/openocd/quiet_blue_led.cfg -c 'init; quiet_blue_led; shutdown'
```

Скрипт переводит PB2 в аналоговый режим и возобновляет ядро. После сброса
или выключения питания заводская программа вернёт мигание; повторить команду.
Не запускать скрипт во время тактовых RAM-проб. Вывод и поведение проверены
2026-09-30 через ST-Link; пользователь подтвердил, что светодиод погас.

Аппаратная цель: WeAct Studio STM32H7R3Zx CoreBoard V1.0 с
`STM32H7R3Z8J6`.

Для безопасного подключения и отладки через ST-LINK использовать
`openocd/weact_stm32h7r3.cfg`. Он выбирает правильный Access Port 1 и
намеренно не описывает flash-банки:

```sh
openocd -f embedded/openocd/weact_stm32h7r3.cfg
```

Запись во внешнюю XSPI flash по адресу `0x90000000` требует
отдельного загрузчика WeAct и не должна выполняться через обычный
`stm32h7x` flash driver.

Цель — STM32H7R3. На 2026-09-26 плата подключена, парные DWT-пробы выполнены.
Подключение перепроверять в каждом сеансе. Runtime строится только на
CMSIS и прямых регистрах: без HAL, LL, PAC, Embassy и Cube-generated кода.
Основной кандидат DSP — Rust `no_std`; C-код контроллера не используется.
Исключение возможно только для CMSIS-DSP как отдельно проверенного объекта. Startup,
регистры и IRQ пишутся прямо на Rust. Realtime до DWT/DMA-замера не объявляется.

Текущая проба: успешная сборка `--features control-ports`, затем из корня
`openocd -f embedded/openocd/weact_stm32h7r3.cfg -f embedded/openocd/run_ram_probe.cfg -c run_ram_probe`.
Только RAM, после опыта — `reset run` заводского приложения. Не запускать
старый образ после ошибки сборки. Последние замеры —
`simulation/experiments/control_ports/hardware.json`; новый путь медленнее рабочего.
Архитектурное поручение — `docs/10 Архитектурное решение.md`.

Для первого реального динамика 2026-09-30 выбран имеющийся LM1875, аналоговый
класс AB. Прежний Class-D-план ниже по истории не считать текущей схемой.
STM32 будет измерять клеммные напряжение/ток и связывать их с виртуальным
TDA2050 причинным power-port; прямую широкополосную цифровую ООС без анализа
задержки не замыкаем. Реактивный динамик в Python остаётся автономным
эталоном, а не вторым динамиком в firmware. См. `docs/14 LM1875 как силовой выход.md`.
