# Ограниченное уточнение Newton между временными шагами, 2026-09-27

**Гипотеза проверена с собственной физической памятью. Общий лимит 1–3 поправки в текущих переменных P7 не принят. P7 остаётся базой; realtime и временная точность не закрыты.**

Пользователь имел в виду перенос недосчитанного решения на следующий временной шаг, а не только малое изменение входного сигнала. Во всех опытах конечное приближение продвигает обе истории памяти даже при большой невязке. Следующий шаг решает уравнения уже с этой собственной историей. Подстановки памяти P7, скрытого доведения до сходимости или повторного полного решения нет.

## Что реализовано

Отдельный `firmware/orange-dsp/src/tracking.rs`, тип `TrackingState<K, MODE>`. Физические законы, их производные и коэффициенты скопированы из P7 без изменения; исходные `packed.rs` и `generated_packed.rs` сохранены. Номинальная конфигурация: ручки 0,5, резистивная нагрузка 6,5 Ом, фиксированное питание, BDF2/96 кГц. Один выходной отсчёт 48 кГц содержит два временных шага; это **не** число Newton-поправок. LUT нет.

| MODE | Правило | Результат |
|---|---|---|
| 0 | Ровно K обычных поправок каждого блока из предыдущего решения | Отрицательный на сильном сигнале |
| 1 | Также ограничение диодной поправки 0,1 В и выходов ОУ физическими пределами | Срывы не устранены |
| 2 | Режим 1 + принятые прямые ветви P7 | Срывы не устранены |
| 3 | Прямые ветви P7 + K попыток поправки, до 12 проверок длины каждой | Самый пригодный для дальнейшей диагностики; общий лимит 1–3 всё равно не принят |

Лимит относится к каждому причинному блоку 1/1/2/3/1, не к суммарным 8 неизвестным. В MODE 0/1 это 5K локальных решений за временной шаг; прямые ветви MODE 2/3 убирают часть решений. В MODE 3 проверка длины вычисляет уравнения и производные, но не решает новую Newton-поправку. Поэтому K не равно числу вычислений нелинейностей. При отсутствии улучшения порт остаётся прежним, но конечная физическая память шага всё равно продвигается. При NaN/Inf/вырождении шаг останавливается и отмечается отдельно; в выполненных коротких и длинных host-траекториях таких остановок не было.

`StepResult.converged` у кандидата означает только локальную невязку <= 1e-4. Прежняя проверка величины остаточной поправки не объявляется выполненной. Счётчик `failures_all[0]` в аппаратном JSON поэтому означает превышения этого допуска, **не** замороженные шаги. У контрольного P7 семантика прежняя. Полные старые проверки восстановленных 56 координат посчитаны независимо.

## Вывод и следующая проверка

Newton сходится к корню одной фиксированной задачи. После продвижения приблизительной памяти задача на следующем временном шаге уже другая. Ошибка может затухать, сохраняться или усиливаться; число 2–3 само по себе ничего не гарантирует. Здесь она на части входов сохраняется/усиливается. Это отрицательный результат для исследованного продолжения P7, не доказательство невозможности другого ограниченного решателя и не основание упрощать физику вслепую.

Следующий содержательный опыт — изменить численные переменные/предобусловливание IC3B так, чтобы ограниченная поправка контролировала ошибку внутреннего полюса, а не только остаток по выходному напряжению; затем снова проверить собственные обе истории. Существующее исключение S8 уже исследовано и не должно повторяться как новое. Предсказание решения и повторное использование производных можно объединить с этим опытом, но их успех пока не установлен. Один шаг Halley на тех же плохих начальных точках не является доказанным исправлением накопленной истории. Автоматический возврат к полной точности может ограничить отдельный промах, но последующее точное решение на ошибочной памяти не исправляет прошлое само по себе; нужны контроль накопления или проверяемое повторное прохождение сохранённых шагов.

Не заменять этот вывод новым произвольным допуском, LUT, переходом на N657 или объявлением P6 приемлемым по RMS. Временная сетка пока BDF2/96 кГц, её отдельная точность не закрыта.
