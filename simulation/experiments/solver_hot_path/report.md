# Профиль горячего пути полного решателя

Профиль снят на 4 мс номинального сигнала, 96 кГц, реактивной нагрузке и
контрольном Schur-решателе. Это время Python на компьютере, не оценка STM32.

После аналитических производных, замены скалярного `np.clip`, замораживания
union-find отображения узлов и кэширования Schur-срезов профилированное время
снизилось с 0,721 до 0,515 с, то есть примерно на 29%. Время функции сборки
`residual_jacobian_physical()` снизилось с 0,569 до 0,380 с.

Новый профиль:

- полная сборка residual/Jacobian: 0,380 с, около 74% всего прогона;
- Schur-подготовка и решение шага: 0,096 с, около 19%;
- собственно `numpy.linalg.solve`: 0,025 с, около 5%;
- остальные операции не образуют сопоставимого единственного узкого места.

Следовательно, уменьшение размерности solve уже не является главным резервом.
Нужна сборка законов приборов непосредственно в 28–29-мерном пространстве без
создания полной матрицы 60×60 на каждой пробе line search. Полный вектор следует
восстанавливать только после принятия шага и для диагностических проверок.

Полная квалификационная сетка после оптимизации прошла; численные результаты и
статус float32 не изменились.

Следом line search переведён на остаточный проход без построения Jacobian и без
вычисления неиспользуемых производных приборов. На пяти повторениях короткого
прогона медиана полного и Schur-варианта стала практически одинаковой:
713 и 711 мкс на отсчёт Python соответственно. Исходный контроль до этой серии
изменений занимал около 1286 мкс/отсчёт; суммарное снижение составляет примерно
45%. Это всё ещё не realtime-ядро, но сокращение больше не проигрывает накладным
расходам своей реализации. Полная сетка после изменения повторно прошла.
