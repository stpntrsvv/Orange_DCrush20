# OrangeDCrush20

Физическая схемная модель Orange Crush 20L с целью realtime на STM32H7R3.
Нелинейности, обратные связи и динамическая нагрузка сохраняются; ускорение
начинается с точного исключения линейных неизвестных, как в проекте Big Muff.
Плата подключена; Rust `no_std` и парные аппаратные DWT-пробы работают.
Полный аудиотракт realtime пока не квалифицирован: DMA/I/O, FIR и кабинет
не входят в измеренное время ядра.

## Рабочая структура и полировка, 2026-09-29

Принят BDF2/48 кГц, `bounded48::BoundedState<3,7>`: один шаг на выход,
до трёх попыток на причинный блок с ранним выходом, без LUT и подшагов.
Архитектурный выбор закрыт; ниже сохранена история 2026-09-26.

Пакет TDA в основном ядре сохраняет побитово выход и оба слоя памяти на
полной гитаре 100/250/1000 мВ. Реальный парный H7R3: 8673 / 8878 / 9229
тактов в среднем, экономия 0,600 / 0,672 / 0,709%. Сильный пик 13707,
все измеренные окна 64 отсчёта укладываются в общий бюджет 12500.

На длинном сильном шуме воспроизведены пять превышений невязки IC3A.
Отдельный экспериментальный старт убрал их, но пик к точной сокращённой
f64/48 ещё 72,581 мВ. В основной вариант старт не включён; аппаратный
шумовой замер не запущен из-за сбоя проверки токена доступа.
Подробности и ограничения: [отчёт TDA/шум](simulation/experiments/tda48/report.md).
Продолжение: [NEXT_CHAT.md](NEXT_CHAT.md).

## Текущее состояние, 2026-09-26

Рабочий сравнительный путь `physical-fpu`: ~13,6 тыс. тактов на внутренний
шаг 96 кГц в прежнем образе, ~14,03 тыс. в последнем парном замере.
Новый 19-координатный `control-ports` дал ~17,57 тыс. (+25,2%) и по скорости
не принят. Уменьшение ошибки в коротком f64-тесте не является ускорением.
На выход 48 кГц сейчас нужны два внутренних шага; бюджет всего CPU при
600 МГц — 12 500 тактов на выходной отсчёт, не на внутреннюю поправку.

В существующем `.venv`:

```sh
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python simulation/audit_schematic.py
.venv/bin/python simulation/run_physical_clip.py
.venv/bin/python simulation/run_device_model_validation.py
```

Для независимой AC-проверки нужен `ngspice` в PATH. Исторический первый блок использует
идеальный ненасыщающийся ОУ и проверочные параметры диодов: это численный стенд,
не законченная физическая модель усилителя и не текущий firmware-кандидат.
Полная модель находится в `simulation/orange_full_mna.py`, исполнительные
кандидаты — в `firmware/orange-dsp`. Команды сборки и продолжения — в `NEXT_CHAT.md`.
