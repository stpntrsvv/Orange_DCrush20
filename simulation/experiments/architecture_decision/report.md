## 2. Уравнения и независимая память

Для конденсаторов выбирается лес ветвей с матрицей инцидентности `E`.
Каждая исходная ветвь точно выражается целочисленной комбинацией ветвей леса:
`E_all = E R`. Проверяется точное равенство матриц инцидентности; обрезания
малых чисел нет. Тогда `C = E Γ Eᵀ`, где `Γ = R diag(C_all) Rᵀ`.
Физические состояния `z = Eᵀ v` — напряжения выбранных конденсаторов.

Номинальная схема: все 23 ёмкостные ветви независимы. Добавляются пять
внутренних напряжений TL072/TDA: 28. У Tone=(0,1,0) одна зависимость — 27.
Реактивный динамик добавляет Cm, Le и Lm — 31. Полная таблица по 11
конфигурациям и список ветвей находятся в `structure.json`.

Ранг C сам по себе ещё не определяет минимальную меняющуюся память.
DC-проверка выявила плавающий резистивный остров `tone_in + tone_low`.
Сумма его KCL даёт сохраняющийся заряд:

```text
Q0 = −E12*z_E12 + C8*z_C8 + C5*z_C5 + C6*z_C6
```

При нулевом пуске Q0=0. Следовательно, из 28 энергетических координат
**27 меняются независимо, одна комбинация — постоянный параметр**. На углу
Tone соответственно 26 + заряд, с реактивным динамиком 30 + заряд.
В проверенном прототипе все 28 координат пока хранятся; для минимального
хранения E12 выражается из равенства выше, сама ёмкость и её ток сохраняются.
`structure.json` содержит коэффициенты инварианта; проверяются нулевые
связи острова с G и источниками. Этот резерв одного состояния не решает CPU-бюджет.

Питание и управление затвором в этом быстром прототипе заданы извне.
Существующий `orange_supply.py` имеет четыре динамических напряжения,
`orange_mute.py` — две независимые ёмкости, хотя пять MNA-узлов.
Эти шесть состояний не включены в 28, их общая квалификация не выполнена.
Внешний токовый порт Class-D также ещё не подключён.

Вводятся источники восьми искомых напряжений:

`r = [v_protected, v_A, v_B, v_clip−v_clip_ref, v_C, v_D,
      v_mute_input−v_volume_top, v_power]`.

Первые три заданных источника — INPUT, AUX_L, AUX_R. Условие `Bᵀv=w`
точно параметризуется как `v=T a+F w`, `BᵀT=0`, `BᵀF=I`.
Для BDF2 `α=1,5`, `h=2z_previous−0,5z_previous2`:

```text
L = G + α fs C
(Tᵀ L T) a = Tᵀ(fs E Γ h − L F w)
v = Nh h + Nd w
i_source = −(Bᵀ B)⁻¹ Bᵀ(Lv − fs E Γ h)
z_next = Eᵀv
```

`TᵀLT` решается при подготовке отдельно по десяти пассивным компонентам
размеров 3/4/1/2/13/2/1/2/3/1. Число ненулевых коэффициентов прямого
обновления памяти — 104 по истории и 40 по источникам. Не требуется
вычислять все узлы на каждом шаге. Ёмкостные нагрузки каскадов остаются внутри
этого исключения, включая Tone, обратные связи и Zobel.

Для индуктивности добавляется проводимость `1/(α fs Lk)` и исторический ток
`h_i/α`; её ток становится физическим состоянием. Это реализовано в f64-
прототипе реактивной нагрузки, не в текущем фиксированном Rust-образе.

Для каждого внутреннего полюса ОУ исходное уравнение:

```text
α fs s − fs h_s = clamp(g d − p s, −S, S)
```

решается аналитически:

```text
s = clamp((fs h_s + g d)/(α fs+p),
          (fs h_s−S)/(α fs), (fs h_s+S)/(α fs))
```

Далее остаются уравнения выходного напряжения `v_out−law(s,i_source)=0`,
двух диодных портов и Q1. Нелинейность полюса не удалена: её кусочная
производная входит в локальный Jacobian. Глубокое насыщение вычисляется
устойчивой алгебраической формой, описанной в документе 10.

Трапеции используют `α=2`, один вектор истории, обновляемый `h_next=4z_next−h`.
Начальное состояние и начальные производные нулевые. BDF2-проба начинает
с нулевой двухшаговой предыстории, как прежняя аппаратная проба.

## 3. Граф и границы

Матрицы влияния: `current_influence.csv`, `input_difference_influence.csv`.
Объединённый граф зависимостей законов (не только Jacobian в покое) даёт:

```mermaid
flowchart LR
  P["D6/D7 · 1"] --> A["IC3A · 1"]
  A --> B["IC3B + D4/D5 · 2"]
  B --> C["IC4A + IC4B + Q1 · 3"]
  C --> D["TDA2050 · 1"]
```

Внутри среднего блока есть обратные связи: например, коэффициент тока
IC4A от напряжения IC4B равен `6,82389773e-6` А/В в номинальном BDF2/96k.
Когда ток меняет доступный размах TL072, это полноценная нелинейная связь.
Считать её структурным нулём нельзя. Общие шины питания тоже создадут
обратное влияние, когда будут включены в совместный расчёт.

В проверенных фиксированных конфигурациях будущие совместные блоки
не входят в уравнения предыдущих: `audit_condensed_structure.py` проверяет
нулевые коэффициенты непосредственно, без порога малости. Поэтому один
последовательный проход **с полным решением каждого совместного блока**
решает общую систему. Это не один приближённый проход локальных поправок
старого `physical-fpu`.

Урок Muff проверен по отчётам `port_solver_dimension`,
`block_solver_specialization`, `cascade_solver`, исходникам
`muff_hybrid_active.py` и `full_pedal_working.c`. Полезны независимая память,
физические управляющие координаты, матрица влияния и специализация.
Отчёт Muff также содержит провалы дробления связанных блоков и исправление
ошибки бюджета: 3715 тактов относились к шагу 384 кГц. Его результаты на G474
не доказывают бюджет Orange и не переносятся как «успех Woodbury».

## 4. Независимая квалификация

`qualification_f64.json`, `qualification_f64_final.log`: 16 случаев по 384
шага, исходная f64-MNA с собственным Newton сравнивается с новым сокращением.
Полная невязка нового результата вычисляется из **его собственной истории**
отдельной MNA-сборкой. Максимум <`9,99e-11`, KCL порядка `1e-12` А.
Проверены номинал, 1 В, восстановление, резкий шум, DC, Clean, Gain=0/1,
оба угла Tone, Volume=0/1, 4/16 Ом, фиксированный mute и реактивная нагрузка.
Это короткая сетка, не полная аттестация движущихся ручек/питания/нагрузок.

Дополнительный `dc_ac.json` проверяет установившиеся DC-решения на входах
−1/−0,1/0/0,1/1 В с Q0=0. Один шаг динамической модели сохраняет эти решения
в пределах `1e-8` по масштабированным состояниям. Неподготовленный DC solve
был сингулярен именно из-за неизвестного заряда плавающего острова;
в независимом DC-решателе избыточная KCL-строка заменяется условием Q0=0.
AC 20/97/997/5000/9991/20000 Гц сравнивает линейный переход новой физической
памяти с прямым решением исходной комплексной MNA при
`s=fs*(1,5−2exp(−jω)+0,5exp(−2jω))`. Максимальная относительная разность
`1,12e-11`; непрерывная АЧХ при `s=j2πf` записана отдельно. Это проверка
точного сокращения и памяти, не оправдание ошибки дискретизации.

До повтора локального блока из другой начальной точки шум давал 3 отказа
и 6,6% RMS; первая версия не поддерживала зависимую ёмкость на углу Tone.
Отрицательные результаты сохранены в `qualification_f64.log`. Базис леса
устранил вторую проблему; повтор при неизменной истории — первую.

по 1024 шага: полные f64-файлы исходного решателя, все 56 координат,

## 6. Ошибка времени и ограниченная проверка разных частот

`full_reference_{3072000,6144000}.npz` — новые **полные f64-MNA**,
резистивная нагрузка, 16 мс, 97/997/9991 Гц и биполярная ступень, уровень 0,1 В.
Ни одна из этих траекторий не получена сокращённым решателем.
Последнее сгущение: 0,05152% RMS на совпадающих моментах. Оно является арбитром
этого сигнала и набора параметров, а не доказательством физики настоящего Orange.

`timestep_comparison.json` содержит две раздельные метрики: на всех совпадающих
внутренних моментах и только на выходной сетке 48 кГц. Выходы не нормализуются.
Например, трапеции/384k: 0,768% / пик 1,236 В по внутренней сетке;
0,550% / пик 0,648 В на сетке 48k. Ошибка между отсчётами не прячется.
BDF2/96k даёт 9,891%, трапеции/96k — 4,038% по внутренней сетке.

Трапеции/384k измерены на плате отдельным образом:
`condensed_trap_384.elf`, SHA-256
`a519a3b89958aedf6f16b593fc8dec85f9a720ab56ba4b3cea92355206ddd663`.
Суммы/условия — `condensed_trap_384.json`; средний шаг 100 мВ 13 238,1,
максимум 15 969. В этом образе период треугольника 384 шага означает **1 кГц**,
а не 250 Гц. Контроль остаётся BDF2/96k: его траекторию не используют для
сравнения точности разных частот. Эта проба измеряет стоимость кандидата;
независимая точность трапеций проверена f64 на ПК, не полной MCU-сеткой.
Восемь шагов требуют около 105 905 тактов на выходной отсчёт. Устройство
в целом не может быть принято на основании этой реализации.

`multirate.json`: четыре локальных группы имеют собственные ёмкости и полюса.
Границы — b_plus, c_plus и power_plus. После точного объединения обратных
связей передаются только напряжения ненагруженных входов макромоделей;
входной импеданс реальной модели уже входит в пассивный расчёт передающего блока.
Здесь у макромоделей входы бесконечноомные — это свойство принятой физики.

Вход+IC3A / IC3B / IC4A+IC4B+Q1 / TDA, трапеции:

| Частоты, кГц | RMS на общей сетке 48 кГц | Пик, В |
|---|---:|---:|
| 384 / 384 / 384 / 384 | 0,550% | 0,648 |
| 96 / 384 / 96 / 96 | 3,814% | 2,959 |
| 192 / 384 / 96 / 192 | 2,578% | 1,564 |

Офлайн используется линейная интерполяция граничных напряжений. Для потока

текущая проверка не реализует power-port и не доказывает его устойчивость.
Простого повышения частоты только IC3B недостаточно. Эти варианты не приняты,
поэтому их аппаратное ускорение не объявляется.

## 7. Что действительно переносится из опыта Muff

Сверены отчёты `port_solver_dimension`, `block_solver_specialization`,
`cascade_solver` и связанные реализации в соседнем BigMuffDPi. Файлы Muff
не изменялись. Его опыт не подтверждает тезис «меньшая система автоматически
помещается в realtime»:

- Разделение связанных Q4/Q3 давало огромные ошибки и расходимость;
  объединение в 3×3/4×4 и повторная поправка Q1 определялись связями и
  измеренной ошибкой. В Orange аналогичный запрет относится к разрыву
  нагрузочной связи IC4A/IC4B/Q1, но сами приборы и уравнения другие:
  здесь присутствуют пять внутренних полюсов, slew и токозависимый размах ОУ.
- Специализация надёжного маршрута Muff сократила аппаратную стоимость
  4176→3615 тактов, дешёвого — всего 3539→3532. Выигрыш относится к конкретной
  реализации сборки/решения, а не к названию метода. В Orange это также
  проверено полным шагом после специализации нового ядра.
- В уточнении `cascade_solver/report.md` прямо исправлена единица бюджета:
  3715 тактов относятся к шагу **384 кГц**, при доступных 442 на G474/170 МГц.
  Этот каскадный вариант Muff сам превышал бюджет примерно в 8,4 раза.
  Нельзя приводить данный отчёт как доказательство готового realtime или
  переносить его такты между разными MCU.

Полезный перенос — физические координаты, точное исключение линейной части,
сохранение связанных нелинейностей в совместном блоке, затем специализация
и проверка всей истории/шага. Доказательство частоты интегрирования и бюджета
остаётся отдельным для Orange. Ни Woodbury, ни каскадность сами по себе его
не заменяют.

## 8. Воспроизведение и ограничения

Из корня Orange, с Rust в PATH:

```sh
.venv/bin/python simulation/audit_condensed_structure.py
.venv/bin/python simulation/validate_condensed_dc_ac.py
.venv/bin/python simulation/run_condensed_qualification.py
.venv/bin/python simulation/run_condensed_reference.py
.venv/bin/python simulation/run_condensed_timestep.py --simulate
.venv/bin/python simulation/run_condensed_multirate.py
.venv/bin/python simulation/generate_condensed.py --rate 96000 --method bdf2
cd firmware
cargo fmt
cargo test -p orange-dsp --release --target aarch64-apple-darwin -- --include-ignored
cargo run -p orange-dsp --example condensed_di --release --target aarch64-apple-darwin
cargo build -p h7r3-runtime --bin ram-probe --release --features condensed-probe
```

**Только после успешной сборки**, из корня:

```sh
openocd -f embedded/openocd/weact_stm32h7r3.cfg -f embedded/openocd/run_condensed_probe.cfg -c run_condensed_probe
```

Сценарий пишет только RAM, сохраняет траекторию в локальный файл и выполняет
`reset run`. Для профиля прежнего пути сборка `--features control-profile`,
сценарий `run_ram_probe.cfg -c run_ram_probe`.

Генератор нового ядра отдельный; `generated_model.rs` прежнего пути не меняется.
После опыта трапеций **возвращены BDF2/96k и успешно пересобран текущий образ**.
Финальные данные — именно `condensed_release_96.*`; другие журналы относятся
к своим снимкам, не к текущему исходнику.

Открытые ограничения: норматив временной/слуховой ошибки, подходящий бюджету
интегратор, полный набор сильных входов, длинная f64-DI, динамические ручки,
переключение топологий, совместное питание/mute и пуск, причинный Class-D-порт,
DMA/I/O, верхняя граница полного времени и стека. Резистивный Rust-образ нельзя
выдать за готовую реактивную или аппаратную нагрузку. Ни один из этих пунктов
не закрывается нулём отказов в короткой пробе.
