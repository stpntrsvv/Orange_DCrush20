# Решатель в 19 управляющих координатах

Дата: 2026-09-26. Статус: аппаратный замер выполнен после подключения платы.
**Ускорения нет: на малом сигнале кандидат на 25,2% медленнее**.
Рабочий `physical-fpu` и основной `step` не заменены.

Каждый вход: 1024 шага, первые 32 исключены, время включает защитный возврат.
FPU-корни и CORDIC-экспоненты у обоих путей. Сборка `--features control-ports`.

Ноль возвратов на 100 мВ показывает: удорожание есть в самом новом пути,
не только в страховочном повторном расчёте. Какие именно стадии его создают,
этот замер не разделяет. Следующая проверка — профиль линейной предыстории,
сокращённого решения, восстановления и повторной полной проверки.
Улучшение точности в компьютерном f64-тесте не означает ускорения на плате
и не является аппаратной квалификацией точности CORDIC.

Сырые слова и SHA-256 образа — `hardware.json`, журнал — `ram_probe.log`.
Оба запуска завершились маркером `DONE`; выполнен `reset run` заводского
приложения после каждой пробы. Flash не изменялась.

## Что изменено

Для полной системы `L x + P phi(Q x) = b` заранее вычисляются
`H = Q L^-1 P` и линейная предыстория `qL = Q L^-1 b`.
На шаге решается `q - qL + H phi(q) = 0`.

19 координат:

- напряжение D4/D5 и напряжение общего узла D6/D7;
- два потенциала канала JFET при прежнем фиксированном затворе;
- для каждого из четырёх TL072 — внутреннее напряжение, выходной ток,
  разность входных напряжений;
- те же три координаты для TDA2050.

Законы нелинейностей прежние. Сохраняются пять локальных блоков по 14
воздействиям, два шага Newton, восемь проб поиска шага. Общего решателя
19×19 в прошивке нет: плотный f64-решатель используется только в тесте.
Линейная предыстория вычисляется один раз, поиск шага работает с 19 координатами.
Все 56 состояний восстанавливаются один раз в конце пробного шага:
`x = L^-1 (b - P phi(q))`. Нелинейности после восстановления вычисляются заново,
проверяются все исходные строки с прежним порогом `1e-4`.
Хранилище текущего и предыдущего состояния пока остаётся 56-мерным.

Промежуточная норма — максимум масштабированного дефекта 19 координат и
изменения пяти ограниченных slew-законов между `q` и `q + rhs`. Это другая
метрика поиска шага; равенство финального порога не делает траектории
побитово одинаковыми. Масштабы напряжений/токов взяты из прежних масштабов
состояния. Slew-норма использует исходные пределы 16 и 8 МВ/с, а не
подобранный слуховой допуск. Никакие нелинейности не вырезаны.

Если итоговая полная проверка не проходит, пробное состояние **не записывается**.
Рабочий физический решатель повторяет тот же шаг из неизменённой предыстории.
Его отказ не скрывается. Это защитный возврат, а не доказательство устойчивости
на сильном сигнале. Его стоимость входит в полный замер, число возвратов
выводится отдельно.

## Независимый полный f64-эталон

1024 отсчёта, 96 кГц, треугольник 250 Гц, нулевой пуск BDF2, резистивная
нагрузка, ручки по 0,5. Эталон `run_absolute_ports_reference.py` использует
полную MNA, остаточная ошибка каждого шага `<2e-9`.
RMS ниже — `sqrt(sum((y-y_ref)^2)/sum(y_ref^2))`.

| Вход | Новый путь: RMS / пик | Рабочий путь: RMS / пик | Отказы нового / рабочего | Возвраты |
|---|---|---|---|---:|
| 100 мВ | 0,002676% / 0,000735 В | 0,2658% / 0,2245 В | 0 / 0 | 0 |
| 1 В | 121,666% / 41,9983 В | 121,669% / 41,9994 В | 698 / 698 | 705 |

На малом сигнале ошибка примерно в 99 раз меньше. На 1 В **оба варианта
не прошли квалификацию**; совпадение плохих результатов не считается успехом.
Это программные экспоненты и FPU-корни компьютера, не аппаратный CORDIC.

## Отрицательные промежуточные опыты

Без проверки slew-дефекта на коротком тесте 100 мВ: RMS 0,2113%, пик
0,14375 В, 146 отказов (динамические строки 50, 51, 52, 55).
Проверка slew-дефекта устранила эти отказы и существенно уменьшила ошибку.

Без защитного возврата при неуспехе полного шага: на 1 В 1022 отказа/1024,
RMS 124,17%; длинная DI 100 мВ застряла и дала 6 616 652 отказа. Отчёт
`../di_rust/report_control_ports_100.md` сохранён как отрицательный результат,
он **не относится к финальному защищённому кандидату**.

## Проверки и оставшиеся ограничения

- Совпадение всех 14 нелинейных значений при переходе `x -> q -> expand(q)`.
- Локальные решения против плотного f64-Jacobian `I + H D` на шести ветвях;
  прежний допуск `max(0,003*abs(delta), 2e-5)` не расширен.
- Независимая сборка полной невязки после каждого шага короткого потока.
- Возврат на сильном сигнале побитово совпадает с рабочим решателем,
  запущенным из снимка предыстории до пробного расчёта.
- Release: 20 тестов, включая два явно запускаемых эталонных опыта;
  debug: 18 обычных тестов, два эталонных опыта по умолчанию пропущены.
- RAM-образ H7R3 собирается; после подключения ST-Link два аппаратных
  запуска завершились. Результат по скорости отрицательный, см. таблицу выше.

Не проверены на новом пути вся сетка ручек, смена режимов, реактивная нагрузка,
сгущение шага и качество полного DI относительно f64. Реальное время не закрыто.
Следующий шаг — профиль стадий на плате, затем сокращение стоимости
линейной предыстории/восстановления по измеренному профилю, а не по ожиданиям.

## Команды

Из корня:

```sh
.venv/bin/python simulation/generate_rust_model.py
.venv/bin/python simulation/run_absolute_ports_reference.py
cd firmware
cargo fmt
cargo test -p orange-dsp --release --target aarch64-apple-darwin -- --include-ignored
cargo run -p orange-render --release --target aarch64-apple-darwin -- control_guard_100 0.100 control-ports
cargo run -p orange-render --release --target aarch64-apple-darwin -- control_guard_250 0.250 control-ports
cargo build -p h7r3-runtime --bin ram-probe --release --features control-ports
```

После успешной сборки, из корня, с подключённой платой:

```sh
openocd -f embedded/openocd/weact_stm32h7r3.cfg -f embedded/openocd/run_ram_probe.cfg -c run_ram_probe
```

В `STEP_PROFILE_*` слова 18–29 сохраняют прежний формат полного парного замера;
**слово 9 — число защитных возвратов на 992 измеряемых шагах**.
Остальные поля стадий для этого кандидата не заполняются.
RAM-проба возвращает заводское приложение через `reset run`.
